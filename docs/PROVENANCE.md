# Provenance

PayNexa is an independently designed and implemented project. This file records where it came from, accurately.

## History

1. The workspace originally held a clone of a public GitHub repository that has no license file
   (`LucasContesini/distributed-payment-platform`). Under default copyright rules, that code cannot be reused,
   modified or redistributed without the author's permission.
2. That tree, including its Git history and a small amount of follow-up work done on top of it, was moved
   unmodified into `_archive/upstream-derivative/`. It is excluded from this repository through `.gitignore`
   and is not built, shipped or referenced by this project.
3. This repository (`main`) starts from a fresh `git init`. Its history contains only commits made for PayNexa.
   No upstream commits are imported, and none are fabricated or rewritten.

## What "independent" means here, honestly

- No upstream source file was copied, translated or mechanically transformed into this codebase.
- The requirements come from the project owner's written specification and from standard payment-engineering
  practice (double-entry bookkeeping, idempotency keys, transactional outbox, etc.). These are ideas and
  techniques, not anyone's code.
- Architecture, data model, package structure, state machine, SQL schema and tests were designed from those
  requirements. They differ materially from the archived project: different service boundaries (the money path is one
  transactional service), asymmetric JWT signing, SQL-first persistence, a real double-entry journal enforced by
  the database, an external-rail model, and so on.
- **Limit of the claim:** the author of this code (an AI assistant working in this repository) read the upstream
  source earlier in the same working session while auditing it. This is therefore not a formal "clean room" in
  the strict legal sense, where the people writing code never see the original. If strict clean-room status
  matters for legal reasons, have the code reviewed by someone qualified, or re-implement the specific parts they
  flag. Nothing here claims legal clearance.

## Third-party code

Only open-source dependencies resolved from Maven Central, listed in `gradle/libs.versions.toml` and the Gradle
build files. The Gradle wrapper files (`gradlew`, `gradlew.bat`, `gradle/wrapper/gradle-wrapper.jar`) are
generated by Gradle (Apache-2.0) and were copied from the archived tree's wrapper, which was itself generated by Gradle.
The distribution checksum in `gradle-wrapper.properties` was verified against the one published by Gradle.
